## Findings — verified 2026-08-05, production build (`next build` 16.x / Turbopack), Chrome

**Both falsification targets survived. Neither spec claim was falsified.**

1. **Stylesheet import order IS preserved by a real Next 16 / Tailwind v4 /
   Turbopack production build.** The emitted CSS is a single file with one
   `@layer theme, base, components, utilities` structure; within `@layer base`
   the source order is exactly the documented contract: preflight (byte 2805)
   → package RichText block (6460) → package `.h1–.h4` (8480) → template base
   rules (8745). Computed-style proof: `h2` inside `.sankara-richtext`
   resolves 26.2px / 600 (package defaults beat preflight; preflight alone
   would give 16px / 400), and the template's same-layer `.h1–.h6
   { font-weight: 500 }` twin applies on top of the package's font-size —
   i.e. the consumer wins ties by source order, per D4 row 2. One nuance:
   Tailwind v4 **merges `@theme` blocks** — a consumer token override
   (`--color-primary: #09b3af`) replaces the package default inside the single
   emitted `:root`, so token overriding is order-independent at the emitted-CSS
   level (it is resolved at build time, not by the cascade).
2. **Heading's unnamespaced `.h1–.h6`: no collision in this template.** Census
   of the built CSS shows exactly five `.hN` rules: the package's four
   (`font-size`/`line-height` only) and the template's deliberate weight rule.
   The template previously had zero `.hN` classes, so the first consumer twin
   was written by this integration, on purpose, as the weight layer the
   package deliberately omits.
3. **`@source "../node_modules/@sankara-ui/core"` is present and load-bearing**:
   package-internal utilities (`.snap-x`, the `popover-open:` variant) exist in
   the built CSS only because of it.

Interactions verified in the served production build: FAQ exclusivity
(`<details name>`, zero JS), Dialog lightbox (opens `:modal`, `aria-label`
from alt text, Escape closes, `<html>` scroll lock engages and releases),
Popover (opens anchored `top-start`, light-dismisses on a real outside
click — synthetic `.click()` does not trigger light dismiss), Carousel dot
navigation scrolls the snap track. Console clean.

### Interop findings for the package (candidates for the next release)

- **`Button` works as `Popover` trigger — but accidentally.** Popover's
  `cloneElement` injects `popoverTarget`/`popoverTargetAction`; Button's
  default branch forwards them only because unknown rest props are spread onto
  the native `<button>`. `ButtonProps` does not declare them, so TypeScript
  neither guarantees nor documents the interop. Verified working at runtime;
  the package should make it contractual (declare popover attrs in
  `ButtonProps`, or document the pattern in both specs).
- **`RichText`'s direct-children contract vs SDK renderers.** Storyblok's
  `StoryblokServerRichText` emits its own wrapper `<div>`, which would kill
  flow spacing and the measure. Its `wrapper={false}` prop composes cleanly:
  `<RichText><StoryblokServerRichText wrapper={false} …/></RichText>`. Worth a
  README example — every Storyblok consumer will hit this.
- **Heading `level` mapping**: stays in the blok (see roadmap Decisions). A
  two-value option field makes it a one-line ternary; the package API stays
  numeric.
- **Popover panel default width** (36rem via `max-w`-equivalent styling) is
  wider than small viewports; the panel clamps to the viewport edge. Cosmetic;
  consumers constrain via `className`. Note for the Popover spec.

### Template fixes that fell out

- `--font-sans: 'Roboto', 'sans-serif'` — the quoted generic made the whole
  stack invalid as a keyword, and Roboto is never loaded, so the site rendered
  in the browser serif default. Fixed to `Roboto, sans-serif`.
- The dead `prose` class (no typography plugin installed) is gone; RichText
  owns body-copy styling now.
